# ۰۱ ـ معماری، محدوده و وضعیت پروژه

[فهرست مستندات](README.md)

## هدف

نسخهٔ سفارشی برای استفادهٔ فارسی، انتخاب زبان فارسی/انگلیسی، رابط RTL، هویت سازمانی، فونت وزیر و نمایش و انتخاب تاریخ شمسی آماده شد. داده‌های کسب‌وکار همچنان با قراردادهای اصلی برنامه ذخیره می‌شوند.

## معماری مرتبط

| لایه | فناوری یا مسئولیت |
| --- | --- |
| Backend | Ruby on Rails، مدل‌ها و سرویس‌های OpenProject |
| پایگاه داده | PostgreSQL؛ نسخهٔ ۱۷ در staging و استقرار ثبت‌شده |
| رابط | ERB و ViewComponent، Turbo و Stimulus، بخش‌های باقی‌ماندهٔ Angular/TypeScript |
| ترجمه | Rails I18n و خروجی i18n-js برای frontend |
| طراحی | استایل‌های برنامه و متغیرهای Primer |
| تاریخ | formatterهای Rails و frontend، Moment/timezone و `jalaali-js` |
| اجرا | Docker با سرویس‌های مستقل web، worker، cron و اجزای زیرساختی |

فایل [version.rb](../lib/open_project/version.rb) نسخهٔ این checkout را `18.0.0` معرفی می‌کند. نسخهٔ Rails مشاهده‌شده در اجرای نهایی Production برابر `8.1.4` بود؛ برای نیازمندی‌های دقیق build باید lockfileها و Dockerfile همان revision بررسی شوند، نه صرفاً یک نسخهٔ تقریبی در توضیحات قدیمی.

## دو نوع تغییر مستقل

### شخصی‌سازی روی کد نسخهٔ ۱۸

مقایسهٔ `d0d7ca836aa..cdd80923d5b` تغییرات خودمان را نشان می‌دهد: ترجمه، استایل، دارایی گرافیکی، formatter و picker تاریخ، تست‌ها، مستندات و ابزار ساخت. فهرست کامل در [تاریخچه و فایل‌ها](14-history-and-file-inventory.md) آمده است.

### ارتقای Production از 17.6 به 18

سرور در بررسی اولیه `17.6.0` بود. استفاده از ایمیج سفارشی ۱۸ برای آن سرور، یک ارتقای نسخهٔ اصلی بود و به ۸۲ migration موجود در نسخهٔ بالاتر نیاز داشت. این migrationها را نباید «۸۲ تغییر دیتابیس برای ترجمهٔ فارسی» دانست؛ موضوع آن‌ها تغییرات upstream مانند ساختار workflow، type، فرم‌ها، ویکی و تنظیمات دسترسی است.

ابتدا فقط انتقال و تمرین روی کپی پشتیبان انجام شد. پس از توضیح تفاوت نسخه‌ها و دریافت تأیید صریح کاربر برای پشتیبان و ارتقا، تغییر Production اجرا شد.

## محدودهٔ پیاده‌سازی

- بهبود ۸۹۸ ترجمه و افزودن ۱۰ مقدار جاافتاده در مرحلهٔ نخست.
- فعال شدن فارسی و اضافه شدن انتخاب زبان در header، حتی پیش از ورود.
- محدود شدن گزینه‌های header به فارسی و انگلیسی.
- اصلاح جهت صفحه و رفتار تغییر اندازهٔ منوی اصلی در RTL.
- استفادهٔ محلی از فونت وزیر و جایگزینی لوگو در مصرف‌کننده‌های اصلی.
- نام نمایشی کامل سامانه، footer سازمانی و هماهنگی پیام‌ها و metadataهای نمایشی.
- نمایش و ورود تاریخ شمسی در مسیرهای مشترک و حفظ تاریخ میلادی برای زبان انگلیسی.
- build کامل، staging جدا، آزمون‌های متمرکز، ارتقای Production و مسیر بازیابی.

## حدود حفظ داده و منطق

در لایهٔ شخصی‌سازی، namespaceها، URLها، شناسه‌های API، قرارداد OAuth و سازوکار احراز هویت برای تغییر نام تجاری بازنویسی نشدند. تبدیل تقویم در لایهٔ ارائه و ورودی صورت می‌گیرد؛ زمان‌بندی و قرارداد ISO میلادی باقی می‌مانند.

خود ارتقای نسخهٔ اصلی می‌تواند ساختار داده و تنظیمات دسترسی را تبدیل کند. بنابراین «منطق احراز هویت را برای فارسی‌سازی تغییر ندادیم» به معنی «ارتقای ۱۷ به ۱۸ هیچ تغییر schema یا permission ندارد» نیست.

نام پروژه‌ها، نام کاربران، متن‌های واردشده، وضعیت‌ها و سایر محتوای ذخیره‌شده برای حذف واژهٔ OpenProject به‌صورت انبوه تغییر نکردند. حساب آزمایشی تمرین بازیابی فقط در دیتابیس محلی جدا ساخته شد؛ حساب یا رمز Production برای آزمون تغییر نکرد.

## محیط‌ها

| محیط | هدف | جداسازی |
| --- | --- | --- |
| checkout محلی | توسعه، build و نگهداری | مخزن `D:\MyProject\openproject` |
| `openproject-fa-staging` | آزمون نسخهٔ سفارشی | دیتابیس و volumeهای مستقل؛ web روی loopback پورت ۱۸۰۸۰ |
| دیتابیس آزمون | RSpec | `openproject_fa_test`؛ جدا از دیتابیس staging |
| تمرین بازیابی محلی | بررسی دادهٔ واقعی روی کپی | پروژهٔ `openproject-prod-rehearsal-20261114`؛ پس از آزمون متوقف شد |
| Production | استفادهٔ واقعی | پروژهٔ Compose به نام `openproject` در `/opt/apps/openproject` |

نام یا پورت مشابه، نشانهٔ یکسان بودن دو محیط نیست. مثلاً پورت ۱۸۰۸۰ محلی این پروژه را نباید با سرویسی روی همان شمارهٔ پورت در سرور اشتباه گرفت.

## وضعیت و اعتبار گزارش

آخرین بررسی واقعی استقرار در ۲۰۲۶-۱۱-۱۴ نشان داد نسخهٔ ۱۸ سالم است، `default_language=fa` و migration معوق وجود ندارد. این مستندات در ۲۰۲۶-۱۱-۱۶ از روی شواهد تدوین شده‌اند و وضعیت لحظه‌ای بعد از آن تاریخ را تضمین نمی‌کنند.

برای جزئیات رفتار رابط، فصل‌های ۲ تا ۷؛ برای عملیات، فصل‌های ۸ تا ۱۲؛ و برای موارد باز، [راهبری و عیب‌یابی](13-maintenance-and-troubleshooting.md) را بخوانید.
