# ۰۲ ـ ترجمه و پوشش زبان فارسی

[فهرست مستندات](README.md)

## مسئله و نتیجه

زبان فارسی در زیرساخت ترجمه وجود داشت، اما در فهرست پیش‌فرض انتخاب زبان فعال نبود و در برخی فرم‌ها و ماژول‌ها متن انگلیسی، ترجمهٔ نامناسب یا کلید جاافتاده دیده می‌شد. مرحلهٔ نخست ۸۹۸ مقدار موجود را بهبود داد و ۱۰ مقدار جاافتاده را در مجموع ۲۳ فایل ترجمه افزود.

این اعداد دامنهٔ مرحلهٔ نخست‌اند. تغییر نام سامانه، footer و پیام اعتبارسنجی تاریخ در مراحل بعد، فایل‌ها و کلیدهای بیشتری را تغییر دادند؛ نباید همهٔ تغییرات نهایی را به همان ۲۳ فایل محدود دانست.

## محل منابع

| مسیر | کاربرد |
| --- | --- |
| `config/locales/en.yml` | متن مرجع انگلیسی backend |
| `config/locales/js-en.yml` | متن مرجع انگلیسی frontend |
| `config/locales/crowdin/fa.yml` | ترجمهٔ فارسی backend |
| `config/locales/crowdin/js-fa.yml` | ترجمهٔ فارسی frontend |
| `config/locales/crowdin/fa.seeders.yml` | متن‌های فارسی داده‌های اولیه |
| `modules/*/config/locales/` | ترجمه‌های هر ماژول |
| `config/locales/generated/fa.yml` | دادهٔ تولیدشدهٔ CLDR |
| `config/i18n.yml` | پیکربندی خروجی ترجمه برای JavaScript |
| `frontend/src/locales/fa.json` | خروجی تولیدشده؛ مرجع ویرایش دستی نیست |

Rails منابع اصلی را از تنظیمات برنامه و منابع ماژول‌ها را از engineها بارگذاری می‌کند. مرحلهٔ export، ترجمهٔ قابل‌مصرف frontend را پیش از build تولید می‌کند.

## حوزه‌های بازبینی

ترجمه‌های فرم‌ها، لغو عملیات، بسته‌های کاری، مدیریت، واردسازی CSV، گردش‌کار، automation و تنظیمات AI بازبینی شدند. ماژول‌های مرتبط شامل avatars، backlogs، BIM، boards، costs، یکپارچه‌سازی GitHub/GitLab، LDAP، meeting، OpenID Connect، reporting، resource management، storages، two-factor authentication، webhooks و wikis هستند.

در منابع تغییرکرده، به «ی» و «ک» فارسی، یکدستی عبارت‌های رابط، حفظ نام محصولات و حفظ مقدار فنی توجه شد. نام‌هایی مانند GitHub، OAuth و CSV بنا بر کاربرد فنی می‌توانند انگلیسی بمانند.

## ممیزی ترجمه

اسکریپت [check_persian](../script/i18n/check_persian) با کتابخانهٔ استاندارد Ruby اجرا می‌شود و برای خود این بررسی نیازی به boot برنامه یا اتصال به PostgreSQL ندارد:

```sh
ruby script/i18n/check_persian
```

بررسی‌ها شامل کلید و leaf جاافتاده، آرایه، شکل مفرد/جمع، کلید تکراری YAML، placeholder، HTML، لینک Markdown، inline code، خرابی متن و مقادیر انگلیسی با allowlist فنی است. placeholderها و قراردادهای ماشینی نباید در ترجمه تغییر کنند.

| مرحله | پوشش و نتیجه |
| --- | --- |
| مرحلهٔ نخست | `10,514 / 10,514` leaf؛ صفر خطا؛ ۸۱ مقدار انگلیسی فنی |
| ممیزی با منابع انگلیسی seed تولیدشده | `10,910 / 10,910`؛ صفر خطا در آن محیط |
| منابع موجود در ایمیج نهایی | `10,517` leaf؛ صفر خطا؛ ۷۸ مقدار انگلیسی فنی |

تفاوت شمارش به منابع موجود و تولید منابع seed و کلیدهای اضافه‌شده در مراحل مختلف وابسته است. تعداد بیشتر یا کمتر به‌تنهایی نشانهٔ بهبود یا افت پوشش نیست. برای مقایسه باید revision و مجموعهٔ ورودی یکسان باشند.

## بازتولید خروجی frontend و بررسی placeholder

در محیط توسعه یا آزمون با وابستگی‌های درست:

```sh
bundle exec rails assets:export_locales
bundle exec i18n-tasks check-consistent-interpolations --config config/i18n-tasks-all-files.yml --locales fa
```

برای تولید منابع مرجع seed، فقط در محیط توسعه/آزمون مناسب:

```sh
bundle exec rails runner script/i18n/generate_seeders_i18n_source_file
ruby script/i18n/check_persian
```

اجرای اسکریپت تولید متن seed با اجرای `db:seed` یکسان نیست. برای اصلاح ترجمه روی Production، seeder را مجدداً اجرا نکنید.

## منابع ترجمه در برابر دادهٔ ذخیره‌شده

تغییر فایل locale، محتوای موجود در دیتابیس را ترجمه یا rename نمی‌کند. عنوان پروژه، نام شخص، توضیح بستهٔ کاری، نام وضعیت‌های قبلاً ساخته‌شده و welcome/consent ذخیره‌شده ممکن است همان زبان قبلی را داشته باشند. بررسی چنین متن‌هایی باید با تشخیص محتوای کاربر و از طریق مدیریت مناسب انجام شود.

زبان انگلیسی fallback باقی مانده است. عبور ممیزی از نظر کلیدها، تضمین ترجمهٔ تمام پاسخ‌های سرویس‌های خارجی، مستندات انگلیسی یا تمام متن‌های ذخیره‌شده نیست؛ تأیید کامل زبانی همچنان بازبینی انسانی می‌خواهد.

## نگهداری

1. ابتدا کلید انگلیسی و مصرف‌کننده را پیدا کنید.
2. معادل فارسی را با حفظ placeholder، HTML و مقصد لینک اضافه کنید.
3. متن generated یا JSON خروجی را به جای منبع اصلی ویرایش نکنید.
4. ممیزی و آزمون مربوط به همان مسیر را اجرا کنید.
5. frontend را دوباره export/build و در هر دو زبان بررسی کنید.

Crowdin منبع ترجمهٔ upstream است. این تغییرات یک patch در fork هستند؛ هنگام وارد کردن ترجمهٔ upstream باید حفظ و بازبینی شوند و فایل‌ها به‌صورت کورکورانه جایگزین نشوند.
