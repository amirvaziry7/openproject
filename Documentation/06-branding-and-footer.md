# ۰۶ ـ نام سامانه، هویت سازمانی و footer

[فهرست مستندات](README.md)

## نام نمایشی

نام کامل مورد استفاده:

> سامانه جامع مدیریت پروژه

این عنوان در متن‌های نمایشی منتخب فارسی و انگلیسی، عنوان برنامه و metadataهای مربوط اعمال شده است. برای استقرار، متغیرهای زیر عنوان را صریح تعیین می‌کنند:

```yaml
environment:
  OPENPROJECT_APP__TITLE: "سامانه جامع مدیریت پروژه"
  OPENPROJECT_SOFTWARE__NAME: "سامانه جامع مدیریت پروژه"
```

`OPENPROJECT_SEED__ADMIN__USER__NAME` پیش‌فرض نام نمایشی مدیر در نصب تازه را تعیین می‌کند؛ نام ورود یا رمز حساب‌های موجود را عوض نمی‌کند. متغیرهای seed را برای rename حساب‌های Production به کار نبرید.

## محل تغییرات

| بخش | فایل یا حوزه |
| --- | --- |
| پیش‌فرض عنوان و نرم‌افزار | `config/constants/settings/definition.rb` |
| متن‌های رابط | منابع `en` و `fa` اصلی و ماژول‌ها |
| پیش‌فرض دادهٔ تازه | `app/seeders/standard.yml` و seedهای BIM |
| نام نمایشی کلاینت موبایل داخلی | `app/seeders/oauth_applications_seeder.rb` |
| metadata ایمیل | `app/mailers/interceptors/default_headers.rb` |
| توضیح پشتیبان | `app/workers/backup_job.rb` |
| عنوان Lookbook | `config/initializers/lookbook.rb` |
| ورود و layoutها | `app/views/account/` و `app/views/layouts/` |
| صفحهٔ خطای مستقل | `public/422.html` |

در مرحلهٔ تغییر نام، صدها مقدار نمایشی در catalogها و پیش‌فرض‌های seed بررسی شدند. شمارش و فهرست فایل‌های نهایی باید از [فهرست تغییرات](14-history-and-file-inventory.md) گرفته شود، نه از جست‌وجو و جایگزینی تمام رشته‌های مخزن.

## مرز متن نمایشی و شناسهٔ فنی

`OpenProject` در namespace Ruby، نام کلاس، import، شناسهٔ API، URL، نام package، مثال کد و copyright upstream می‌تواند باقی بماند. حذف سراسری آن قراردادهای فنی را خراب می‌کند.

نام نمایشی OAuth تغییر کرده، اما UID، redirect URI و پروتکل آن به خاطر نام‌گذاری عوض نشده است. header ایمیل `X-Mailer` از نام نرم‌افزار استفاده می‌کند و رگرسیون Unicode آن آزمون شده است. نام فنی فایل‌های پشتیبان و مسیر ذخیره‌سازی برای نمایش نام تجاری تغییر نکرده‌اند.

نام شخص، پروژه یا متن ثبت‌شده در دیتابیس نیز شناسهٔ ترجمه نیست. برای مثال نام قبلی مدیر یا متن welcome قدیمی ممکن است OpenProject داشته باشد؛ پاکسازی انبوه آن‌ها در Production انجام نشده است.

## متن پایین صفحات

متن درخواست‌شده عیناً در ترجمهٔ `institutional_footer` ثبت شده است:

> تهیه شده در مرکز علوم نوین پدافندی دانشکده و پژوهشکده پدافند غیرعامل دانشگاه جامع امام حسین (ع)

partial مشترک [institution footer](../app/views/layouts/_institution_footer.html.erb) در layout اصلی و layout لوگومحور استفاده می‌شود. متن در رابط انگلیسی هم فارسی است و با `lang=fa` و `dir=rtl` و فونت وزیر نمایش داده می‌شود. صفحهٔ مستقل ۴۲۲ نسخهٔ متناظر خود را دارد.

«پایین صفحات» در این پیاده‌سازی به صفحات تحت این layoutها و صفحهٔ مستقل اصلاح‌شده اشاره دارد؛ الزاماً هر پاسخ API، فایل PDF، ایمیل متنی یا صفحهٔ خارج از این layoutها footer ندارد.

## چیدمان footer

در `_generic.sass` کلاس‌های زیر اضافه شده‌اند:

- `.op-institution-page`: grid با ردیف محتوا و ردیف footer.
- `.op-institution-page-content`: ناحیهٔ قابل scroll با `min-height: 0`.
- `.op-institution-footer`: تراز وسط، فاصله، مرز و شکست متن بلند.

هدف، رزرو فضای footer و جلوگیری از پوشاندن فرم‌ها و جدول‌هاست. برای چاپ، grid به block تغییر می‌کند. overlay ثابت برای قرار دادن پیام روی محتوا اضافه نشده است.

## تنظیمات موجود در دیتابیس

در staging فقط چند تنظیم نمایشی مانند `app_title`، `software_name`، `welcome_title`، `welcome_text` و `consent_info` و نام نمایشی مدیر پیش‌فرض بررسی/اصلاح شدند و مقادیر قبلی در فایل خصوصی پشتیبان نگه داشته شدند.

این عملیات به معنی اجرای همان تغییرها روی تمام داده‌های Production نیست. در استقرار اصلی عنوان با environment تنظیم شد؛ متن‌های welcome/consent ذخیره‌شده و دادهٔ کاربران باید به‌صورت موردی و از راه مدیریت بازبینی شوند.

## نگهداری

برای تغییر دوبارهٔ نام، عنوان environment، منابع دو زبان، پیش‌فرض‌های نصب تازه، email metadata، footer و صفحهٔ ۴۲۲ را هماهنگ کنید. تغییر footer تنها در partial کافی نیست اگر منبع ترجمه یا HTML مستقل هنوز متن قبلی را داشته باشد. تست انگلیسی، ورود، موبایل و صفحهٔ دارای scroll را فراموش نکنید.
