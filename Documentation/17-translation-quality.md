# ۱۷ ـ قرارداد کیفیت ترجمه و ممیزی

[فهرست اصلی](README.md) · [اسکریپت ممیزی](../script/i18n/check_persian)

## مواردی که ترجمه نباید تغییر دهد

| جزء | قرارداد |
| --- | --- |
| `%{name}` | نام placeholder باید با منبع برابر بماند |
| HTML | tagها و attributeهای مورد انتظار حفظ شوند |
| لینک Markdown | متن قابل ترجمه است؛ مقصد فنی بی‌دلیل تغییر نکند |
| inline code | شناسه و قطعهٔ فنی حفظ شود |
| plural/hash/array | شکل ساختار و کلیدها با منبع سازگار باشد |

برای مثال، در ترجمهٔ `Hello %{name}` می‌توان جای placeholder را عوض کرد، اما تبدیل آن به `%{username}` قرارداد فراخوانی را می‌شکند. این مثال آموزشی کلید جدیدی در برنامه ایجاد نمی‌کند.

## رفتار واقعی ممیز

اسکریپت YAML را با Psych بررسی می‌کند، کلیدهای تکراری را از درخت parser می‌یابد و ساختارها را به leaf تبدیل می‌کند. سپس همتای فارسی هر منبع انگلیسی را بررسی می‌کند. نبود counterpart، رشته نبودن مقدار و اختلاف interpolation یا markup گزارش می‌شوند.

مقایسهٔ placeholder بر پایهٔ مجموعهٔ نام‌هاست؛ این بررسی به‌تنهایی تعداد تکرار یا معنای جمله را تأیید نمی‌کند. مقایسهٔ tokenهای markup نیز تضمین کامل accessibility، HTML سالم در تمام حالت‌ها یا ترجمهٔ طبیعی نیست.

## متن فارسی و مقدار فنی

حروف «ی/ک» فارسی و نبود کاراکتر خراب بررسی می‌شوند. رشته‌های کاملاً انگلیسی باید ترجمه یا در allowlist فنی توجیه شوند. افزودن جملهٔ ترجمه‌نشده به allowlist صرفاً برای سبز شدن ممیزی، رفع مسئله محسوب نمی‌شود.

```sh
ruby script/i18n/check_persian
```

خروجی موفق شامل شمار leaf، شمار مقادیر فنی پذیرفته‌شده و `0 errors` است؛ exit code نیز موفق است. شمار leaf به مجموعهٔ منابع تولیدشده وابسته است.

## معیار بازبینی انسانی

پس از ممیزی، خوانایی label کوتاه، یکدستی واژه‌ها، متن دکمهٔ تأیید/لغو، جمع فارسی و نمایش پیام با مقادیر واقعی را بررسی کنید. متن روی موبایل ممکن است wrap شود؛ طول ترجمه یک ویژگی رابط نیز هست. نتیجهٔ زبانی را جدا از نتیجهٔ ساختاری ثبت کنید.
