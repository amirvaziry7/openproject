# ۲۰ ـ چرخهٔ درخواست و session انتخاب زبان

[فهرست اصلی](README.md) · [کنترلر برنامه](../app/controllers/application_controller.rb)

## جریان فعلی

ابتدا `SetLocalizationService` با کاربر و `Accept-Language` زبان عادی درخواست را تعیین می‌کند. سپس `selected_interface_language` در صورت وجود انتخاب معتبر، locale همین درخواست را override می‌کند.

```text
GET ui_language → اعتبارسنجی در valid_languages
                → session[:ui_language]
                → I18n.locale درخواست
                → lang/dir و ترجمه‌های صفحه
```

پارامتر فقط از GET برای این انتخاب خوانده می‌شود. session نامعتبر نیز برای override پذیرفته نمی‌شود. نام کلید session و پارامتر فنی است و به خاطر ترجمه نباید تغییر کند.

## دامنهٔ اثر

انتخاب در مرورگر فعلی نگه داشته می‌شود؛ فیلد زبان حساب در دیتابیس بازنویسی نمی‌شود. مرورگر دوم یا session تازه ممکن است دوباره نتیجهٔ ترجیح کاربر/مرورگر/instance را بگیرد. این تفاوت باید در سناریوی آزمون لحاظ شود.

| سناریو | انتظار |
| --- | --- |
| `GET /login?ui_language=fa` با فارسی معتبر | صفحهٔ فارسی و ذخیرهٔ انتخاب |
| رفتن به مسیر دیگر در همان session | حفظ انتخاب معتبر |
| مقدار ناشناخته | نپذیرفتن مقدار ناشناخته |
| تغییر به `en` | بازگشت LTR و نمایش انگلیسی |

## فرم header

فرم GET در مسیر فعلی، با Turbo غیرفعال، selector و دکمهٔ اعمال را ارسال می‌کند. `back_url` رشته‌ای حفظ می‌شود تا تغییر زبان در صفحهٔ ورود، بازگشت معمول بعد از ورود را بی‌دلیل از بین نبرد. این فرم نباید برای تغییر رمز، مجوز یا هویت کاربر استفاده شود.

در عیب‌یابی، cookie/session، locale پاسخ و redirectهای همان درخواست را کنار هم بررسی کنید. محتوای session یا cookie احراز هویت را در screenshot، لاگ عمومی یا fixture Git ذخیره نکنید. نتیجهٔ آزمون را بدون انتشار storage state ثبت کنید.
