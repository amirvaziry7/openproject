# ۲۲ ـ منوی اصلی، resize و تعامل RTL

[فهرست اصلی](README.md) · [مرور RTL](03-language-selector-and-rtl.md)

## مسئلهٔ اصلاح‌شده

منوی فارسی تنها با `dir=rtl` درست نمی‌شد: موقعیت دستگیره، جهت drag و کلیک پس از drag باید هماهنگ می‌شدند. استایل دستگیره از موقعیت منطقی استفاده می‌کند و chevron فارسی mirror می‌شود.

در [component تغییر اندازه](../frontend/src/app/shared/components/resizer/resizer/main-menu-resizer.component.ts)، عرض ابتدای drag ذخیره می‌شود. delta افقی برای RTL معکوس می‌شود و عرض جدید به سرویس منو می‌رود. RTL از computed direction منو تشخیص داده می‌شود، نه حدس از متن label.

## کلیک پس از drag

مرورگر می‌تواند پس از pointer drag یک click هم تولید کند. اگر هر click منو را toggle کند، کاربر با رها کردن resize ناخواسته منو را می‌بندد. component حرکت بیش از دو پیکسل را ثبت می‌کند و toggle حاصل از آن drag را کنار می‌گذارد؛ کلیک عادی و فعال‌سازی با صفحه‌کلید باقی می‌مانند.

| ورودی | انتظار |
| --- | --- |
| drag در فارسی | افزایش/کاهش عرض متناسب با سمت منو |
| رها کردن drag | حفظ وضعیت باز بودن منو |
| کلیک بدون drag | toggle معمول |
| فعال‌سازی صفحه‌کلید | toggle قابل استفاده |
| همان رفتار در انگلیسی | بدون معکوس شدن اشتباه delta |

## روش بازبینی بعدی

ابتدا جهت واقعی منو و جای دستگیره را ببینید، سپس رفتار event را بررسی کنید. اصلاح هم‌زمان CSS و محاسبه بدون تشخیص می‌تواند دو بار جهت را معکوس کند. سناریو را در منوی باز/بسته و هر دو زبان تکرار کنید.

تست‌های رگرسیون در فایل spec هم‌نام component ثبت شده‌اند. نتیجهٔ اجرای قبلی در [فصل آزمون‌ها](10-tests-and-validation.md) است؛ این راهنما اجرای تازهٔ تعامل محسوب نمی‌شود.
