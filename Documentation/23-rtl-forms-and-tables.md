## جهت متن با جهت مقدار یکسان نیست

صفحهٔ فارسی RTL است، اما مقدار URL، ایمیل، کد، تلفن، عدد و رمز برای خوانایی LTR باقی می‌ماند. استایل برای این ورودی‌ها از جهت و تراز مناسب و isolation استفاده می‌کند. تبدیل عمومی همهٔ اعداد یا عوض کردن ترتیب رشتهٔ رمز بخشی از فارسی‌سازی نیست.

| جزء | رویکرد فعلی |
| --- | --- |
| label فرم | تراز منطقی `start` |
| متن فارسی | جهت به‌ارث‌رسیده از صفحه |
| `pre` و `code` | LTR |
| ورودی‌های فنی مشخص | LTR و isolation |
| بخش timeline گانت | LTR برای محور و محاسبات آن |

## بازبینی جدول

برای یک جدول فقط موقعیت ستون‌ها را نگاه نکنید. عنوان ستون، محتوای فارسی/انگلیسی، عدد، منوی سطر، sort، scroll و دستگیرهٔ resize ممکن است قواعد جدا داشته باشند. نمونهٔ مناسب یک سطر ترکیبی با عنوان فارسی و شناسهٔ لاتین است.

## سناریوی کنترل دستی

1. فرم ورود و یک فرم پروژه/بستهٔ کاری را در فارسی باز کنید.
2. label و مقدار فنی را از هم تفکیک و مکان caret را بررسی کنید.
3. جدول دارای scroll و action سطر را در viewport باریک ببینید.
4. به انگلیسی برگردید و اثر باقی‌ماندهٔ CSS فارسی را کنترل کنید.
5. اگر تغییر وابسته به کلاس است، محدودهٔ selector را ثبت کنید.

همهٔ CSSهای legacy و همهٔ جدول‌ها به‌صورت جامع mirror نشده‌اند. یک اصلاح محلی نباید با selector عمومی، editor یا timeline را تحت تأثیر ناخواسته قرار دهد. نتیجهٔ هر component جداگانه ثبت شود.
