# ۲۴ ـ چرخهٔ دارایی فونت و تشخیص cache

[فهرست اصلی](README.md) · [مشخصات وزیر](04-vazir-font.md)

## از فایل تا متن نهایی

```text
WOFF2 محلی → @font-face → متغیرهای font stack → CSS ساخته‌شده → asset مرورگر
```

هر مرحله می‌تواند علت دیده نشدن فونت باشد. داشتن فایل درست در checkout به معنی وجود آن در image فعال نیست؛ همچنین دریافت WOFF2 به معنی انتخاب آن برای همهٔ متن‌ها نیست.

## روش تشخیص

| مشاهده | برداشت قابل بررسی |
| --- | --- |
| درخواست فونت وجود ندارد | صفحه `fa` نیست، CSS تعریف را مصرف نکرده یا asset قدیمی است |
| درخواست شکست می‌خورد | مسیر، fingerprint، پاسخ سرور یا build بررسی شود |
| دریافت موفق ولی computed family متفاوت | cascade یا خانوادهٔ مخصوص component بررسی شود |
| وزن bold شبیه regular است | فایل و وزن `@font-face` تطبیق داده شود |
| فقط انگلیسی فونت دیگری دارد | رفتار مورد انتظار فعلی است |

در این پیاده‌سازی وزن‌های ۴۰۰، ۵۰۰ و ۷۰۰ از فایل جدا می‌آیند و `font-display: swap` تعریف شده است. برای نسبت دادن تفاوت لحظهٔ بارگذاری به شکست فونت، پس از تکمیل بارگذاری هم بررسی کنید.

## تغییر آینده

نام خانواده، وزن، مسیر WOFF2 و مجوز را یک مجموعه بدانید. پس از تعویض، build تازه و مقایسهٔ image/asset لازم است. پاک کردن cache اختصاصی برنامه، جای build فونت را نمی‌گیرد؛ cache مرورگر نیز مسئله‌ای جدا از cache تنظیمات Rails است.

code و icon می‌توانند خانوادهٔ تخصصی خود را داشته باشند. اعمال `font-family` اجباری به تمام عناصر برای رفع یک component، ممکن است iconها یا خوانایی کد را خراب کند. override باید در همان محدودهٔ معیوب بررسی شود.
