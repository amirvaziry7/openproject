# ۲۸ ـ نمایش و parse تاریخ در frontend

[فهرست اصلی](README.md) · [راهنمای تقویم](07-jalali-calendar.md)

## توابع محوری

در [persian-calendar.ts](../frontend/src/app/core/datetime/persian-calendar.ts)، `formatCalendarDate` فقط برای locale برابر `fa` توکن‌های تاریخ را به نمایش جلالی می‌برد. برای زبان دیگر یا تاریخ نامعتبر، مسیر formatting قبلی حفظ می‌شود.

`parsePersianDate` متن را با الگوی ورودی تطبیق می‌دهد، رقم‌ها را عادی‌سازی و اعتبار روز/ماه/سال را بررسی می‌کند. خروجی آن تاریخ میلادی و بخش ساعت جداست، نه یک رشتهٔ شمسی برای ذخیره در مدل.

| تابع | خروجی/نقش |
| --- | --- |
| `persianMonthName` | نام ماه برای نمایش |
| `formatCalendarDate` | نمایش متناسب با locale |
| `parsePersianDate` | تاریخ میلادی معتبر یا `null` |
| `persianPeriod` | مرز ماه/فصل/سال شمسی برای ارائه |

## استفادهٔ درست

ابتدا روز را در timezone درست کاربر تعیین کنید؛ formatter نمایش نباید جبران‌کنندهٔ انتخاب timezone اشتباه شود. برای مقدار ماشینی از همان قرارداد ISO موجود استفاده کنید و Moment را در سطح global به تقویم شمسی تغییر ندهید.

ورودی چهاررقمی سال ترجیح دارد. parse فعلی سال دو رقمی را با پیشوند `14` می‌سازد؛ این یک فرض واقعی پیاده‌سازی است، نه تشخیص هوشمند هر قرن تاریخی.

## سناریوهای توسعه

برای token یا فرمت تازه، حالت فارسی و انگلیسی، متن literal داخل فرمت، مقدار نامعتبر و round-trip را بررسی کنید. اضافه کردن فرمت نمایشی نباید خروجی `YYYY-MM-DD` در مسیر API را عوض کند. نتیجهٔ الگوریتم در بازهٔ آزموده‌شده ثبت شده است؛ خارج از بازهٔ پشتیبانی کتابخانه ادعای صحت نامحدود نکنید.
