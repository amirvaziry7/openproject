# ۲۹ ـ formatter شمسی در Rails

[فهرست اصلی](README.md) · [پیاده‌سازی Ruby](../lib/open_project/internationalization/persian_calendar.rb)

## محل اتصال

مسیر مشترک `format_date` در `lib_static/redmine/i18n.rb` برای نمایش فارسی به formatter جلالی متصل شده است. منطق تبدیل Ruby از شروع سال و اختلاف روزهای `Date` استفاده می‌کند؛ تبدیل رشتهٔ نمایشی با ذخیره‌سازی تاریخ در مدل یکی نیست.

| متد | مسئولیت |
| --- | --- |
| `year_start` | محاسبهٔ روز شروع سال جلالی |
| `parts` | استخراج سال، ماه، روز و روزِ سال |
| `localize` | جایگذاری directiveهای پشتیبانی‌شدهٔ تاریخ |
| `directive_values` | مقادیر نمایشی directiveها |

بعضی فرمت‌ها همچنان از I18n برای اجزای دیگر استفاده می‌کنند. پشتیبانی از directiveهای مشخص، ادعای پیاده‌سازی مستقل تمام رفتارهای `strftime` نیست.

## خروجی ماشینی

برای پارامتر فرم، timestamp یا filename نباید صرفاً چون زبان فارسی است خروجی شمسی تولید شود. گزینهٔ `calendar: false` در مصرف‌کننده‌های ماشینی مرتبط به کار رفته است؛ از جمله reminder، ورودی جلسه و نام فایل‌های export.

## اصلاح مصرف‌کننده

1. تشخیص دهید متن برای کاربر است یا برای پردازش بعدی.
2. اگر نمایشی است، از helper مشترک استفاده کنید.
3. اگر ماشینی است، قرارداد ISO و opt-out مربوط را حفظ کنید.
4. دو locale و مقدار مرزی سال را در تست مرتبط بررسی کنید.

در مرحلهٔ تقویم، نبود include helper در بخشی از My work آشکار و اصلاح شد. بنابراین اضافه کردن تابع به library به‌تنهایی کافی نیست؛ component مصرف‌کننده نیز باید دسترسی صحیح به آن داشته باشد.

مقایسهٔ الگوریتم با JavaScript و آزمون‌های Rails در فصل ۱۰ ثبت شده‌اند. این فصل توضیح کد موجود است و اجرای دوبارهٔ آن آزمون‌ها محسوب نمی‌شود.
