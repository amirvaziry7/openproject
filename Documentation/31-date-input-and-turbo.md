## دو ورودی با دو نقش

ورودی اصلی نام فرم و مقدار ISO را حفظ می‌کند و در مسیر فارسی می‌تواند hidden شود. یک clone نمایشی text بدون `name` کنار آن قرار می‌گیرد. حذف `name` از clone از ارسال دو مقدار ناسازگار برای یک فیلد جلوگیری می‌کند.

| ویژگی | رفتار adapter |
| --- | --- |
| label | اتصال به شناسهٔ ورودی نمایشی |
| تایپ معتبر | parse شمسی، نوشتن ISO و ارسال eventهای input/change |
| تایپ نامعتبر | custom validity؛ جلوگیری از اعمال مقدار نامعتبر |
| focus | هدایت رویداد مورد نیاز picker |
| disabled/readonly/class | هماهنگ شدن با ورودی اصلی |
| cleanup | قطع observer، بازگرداندن type/label و حذف clone |

## چرا observer لازم شد؟

فرم تاریخ بستهٔ کاری می‌تواند با Turbo preview morph یا replace شود. در مشاهدهٔ اولیه، ورودی نمایشی از DOM حذف می‌شد ولی بخشی از component باقی می‌ماند. observer محدود، ورودی مرتبط را دوباره پیدا و adapter را برای نسخهٔ صحیح بازسازی می‌کند.

این observer به ریشه و شناسه‌های مشخص محدود است. نگهداری listener روی عنصر قدیمی یا observer سراسری برای تمام صفحه، راه‌حل معادل آن نیست.

## آزمون پیشنهادی تغییر بعدی

1. مقدار اولیه و clone نمایشی را تطبیق دهید.
2. تاریخ معتبر و نامعتبر را تایپ کنید.
3. preview را با morph و با replacement آزمایش کنید.
4. از نبود clone تکراری و مقدار فرم اضافی مطمئن شوید.
5. component را ببندید و cleanup را کنترل کنید.

سناریوی لغو باید با reload بررسی کند تاریخ پایدار تغییر نکرده باشد؛ تغییر preview را با ثبت واقعی داده اشتباه نگیرید.
