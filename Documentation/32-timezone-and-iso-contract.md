# ۳۲ ـ منطقهٔ زمانی و قرارداد ISO

[فهرست اصلی](README.md) · [تقویم کلی](07-jalali-calendar.md)

## سه مفهوم مستقل

«تقویم»، «منطقهٔ زمانی» و «فرمت رشته» یک مسئله نیستند. یک لحظهٔ UTC در منطقهٔ زمانی کاربر ممکن است روز دیگری باشد؛ همان روز محلی هم می‌تواند با تقویم شمسی یا میلادی نمایش داده شود.

```text
لحظهٔ ذخیره‌شده → timezone کاربر → روز محلی → نمایش شمسی/میلادی
ورودی محلی → اعتبارسنجی تقویم → روز میلادی محلی → UTC/ISO مناسب مسیر
```

## قرارداد حفظ‌شده

| خروجی | انتظار |
| --- | --- |
| label فارسی | تاریخ شمسی قابل خواندن |
| مقدار API یا فیلد اصلی فرم | ISO میلادی با رقم ASCII |
| datetime | timezone و offset مطابق قرارداد موجود |
| تاریخ بدون ساعت | بدون افزودن خودسرانهٔ معنای «لحظهٔ UTC» |
| attribute ماشینی | مستقل از ترجمهٔ متن صفحه |

تاریخ بدون ساعت را صرفاً برای تبدیل ظاهر به timestamp تبدیل نکنید. همچنین بریدن رشتهٔ UTC برای استخراج روز، همیشه معادل روز کاربر نیست.

## سناریوهای مرزی

برای تغییر formatter یا parser، نزدیک نیمه‌شب، گذر روز، گذر سال، ساعت عصر و ورودی رقم فارسی را بررسی کنید. ابتدا مقدار ذخیره‌شده و timezone را ثبت کنید؛ سپس مقدار نمایش و payload خروجی را مقایسه کنید. حذف timezone از یک مرحله می‌تواند خطای یک‌روزه را به‌اشتباه شبیه خطای الگوریتم شمسی نشان دهد.

در تست‌های ثبت‌شده، round-trip و مرز روز منطقهٔ زمانی بررسی شدند. این نتیجه، تأیید همهٔ timezoneهای تاریخی یا تمام قواعد زمانی آینده نیست. تغییر global تقویم Moment برای رفع یک صفحه، می‌تواند مسیرهای ماشینی دیگر را تحت تأثیر قرار دهد و در این پیاده‌سازی انجام نشده است.
