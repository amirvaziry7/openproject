# ۳۷ ـ معیار جداسازی staging و تمرین restore

[فهرست اصلی](README.md) · [راه‌اندازی محلی](09-local-and-staging.md)

## جداسازی فراتر از شمارهٔ پورت

عوض کردن پورت web، دیتابیس و پیوست را جدا نمی‌کند. نام project، volumeها، DATABASE_URL، مسیرهای bind، network و credential هم باید بررسی شوند. یک staging با URL دیتابیس اصلی، محیط امن آزمون داده نیست.

| جزء | معیار جداسازی |
| --- | --- |
| project | نام مستقل و قابل تشخیص |
| PostgreSQL | دیتابیس و credential آزمایشی |
| فایل پیوست | volume/مسیر جدید |
| web | دسترسی loopback به جای انتشار عمومی ناخواسته |
| ایمیل و job | نبود ارسال واقعی به مخاطبان Production |
| session/secret | دادهٔ آزمایشی مستقل و خصوصی |

## دو محیط استفاده‌شده

staging معمول با `openproject_fa_stage` برای آزمون قابلیت ساخته شد. تمرین restore واقعی پروژهٔ محلی مستقل دیگری بود که کپی dump و پیوست را گرفت و migration روی آن اجرا شد. حساب مدیر آزمایشی همان تمرین نباید به عنوان حساب Production معرفی شود.

در تمرین، web برای مرورگر bridge داشت ولی دیتابیس روی پورت عمومی میزبان منتشر نشد. تنظیم روش تحویل ایمیل آزمون و فعال نکردن worker/cron واقعی از اجرای عملیات جانبی روی دادهٔ کپی‌شده جلوگیری می‌کرد.

## پایان تمرین

متوقف کردن محیط با حذف volume فرق دارد. در عملیات ثبت‌شده، پس از بررسی، محیط restore متوقف و volumeها حفظ شدند. اگر لازم است دادهٔ واقعی کپی‌شده حذف شود، آن تصمیم عملیاتی و محدودهٔ مسیر/volume باید جدا مشخص شود؛ دستور حذف عمومی در این راهنما ارائه نشده است.

موفقیت restore به همراه مقایسهٔ داده مدرک مهمی است، اما snapshot آزمایشی قدیمی جای backup تازهٔ لحظهٔ cutover را نمی‌گیرد.
