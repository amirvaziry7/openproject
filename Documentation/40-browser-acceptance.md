## لایه‌های کنترل

| کنترل | چه چیزی را تأیید می‌کند؟ |
| --- | --- |
| HTTP status | پاسخ مسیر |
| `html lang/dir` | زبان و جهت document |
| computed style | فونت/استایل واقعاً انتخاب‌شده |
| asset decode/hash | دادهٔ واقعی تصویر/asset |
| مقدار فرم و payload | قرارداد ماشینی ورودی |
| reload | تفاوت preview با دادهٔ پایدار |
| screenshot | نتیجهٔ بصری در viewport ثبت‌شده |

این کنترل‌ها مکمل‌اند. HTTP 200 با خطای JavaScript ممکن است و screenshot درست می‌تواند مقدار hidden اشتباه را پنهان کند.

## سناریوی حداقلی این fork

ورود فارسی و انگلیسی، تغییر زبان، منوی RTL، نمایش فونت و لوگو، footer، یک فرم تاریخ و برگشت به انگلیسی بررسی شود. برای موبایل عرض و user agent ثبت شوند؛ کوچک کردن عرض به‌تنهایی همهٔ شاخه‌های مخصوص موبایل را فعال نمی‌کند.

برای تاریخ، هم روز قابل مشاهده و هم ISO اصلی را ببینید. سناریوی لغو را با reload تکمیل کنید. CSP یا تزریق script/style را برای آسان شدن تست نهایی غیرفعال نکنید؛ بررسی تشخیصی با پذیرش image واقعی فرق دارد.

## احراز هویت و حریم خصوصی

در تمرین restore از حساب آزمایشی مستقل استفاده شد. برای تست Production رمز حساب موجود reset نشد. browser storage state و screenshot دارای دادهٔ واقعی ممکن است خصوصی باشند و نباید برای اثبات تست به Git عمومی منتقل شوند.

خطای شناخته‌شدهٔ درخواست ناشناس login را جدا ثبت کنید؛ حذف آن از شمار خطاهای گزارش بدون توضیح، یا ادعای «هیچ خطایی نبود» نادرست است. اگر آن خطا را از معیار شکست یک سناریوی مشخص مستثنا می‌کنید، همان استثنا در نتیجه نوشته شود.
