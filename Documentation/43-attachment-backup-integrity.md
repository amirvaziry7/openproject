# ۴۳ ـ پیوست‌ها، archive و صحت بازیابی فایل

[فهرست اصلی](README.md) · [فهرست backupها](12-backup-and-rollback.md)

## دیتابیس و فایل یک مجموعه‌اند

رکورد attachment در دیتابیس می‌تواند وجود داشته باشد، اما فایل متناظر روی دیسک قابل دسترسی نباشد. پشتیبان فقط از SQL برای بازیابی کامل فایل‌ها کافی نیست؛ همچنین archive فایل‌ها بدون دادهٔ metadata برنامه، جای دیتابیس را نمی‌گیرد.

| کنترل | فایده |
| --- | --- |
| مسیر mount واقعی | جلوگیری از backup مسیر خالی یا اشتباه |
| فهرست archive | امکان خواندن archive و شناخت ساختار |
| metadata/ACL | حفظ دسترسی و مالکیت مورد نیاز |
| hash هر فایل | تطبیق محتوا پس از restore |
| بررسی با برنامه | امکان مصرف فایل با config بازیابی |

## عملیات انجام‌شده

در cold backup، archive پیوست با metadata و ACL تهیه شد. کپی restore در مسیر جدا باز شد و SHA256 هر پنج فایل با اصل برابر بود. فایل‌های فعال Production بازنویسی یا پاک نشدند. برنامهٔ قدیمی نیز با مقصد restore آمادهٔ boot شد.

## checksum چه چیزی را نمی‌گوید؟

SHA256 برابر، همسان بودن دو مجموعه بایت را نشان می‌دهد؛ تضمین نمی‌کند فایل از ابتدا محتوای مطلوب کاربر بوده یا برنامه با permission نادرست هم آن را می‌خواند. کنترل محتوایی، دسترسی و انطباق مسیر باید جدا انجام شوند.

## هنگام بازگشت

پیوست‌های ثبت‌شده پس از backup در snapshot قدیمی نیستند. حفظ مسیر فعال نسخهٔ ۱۸ مانع حذف فیزیکی آن‌ها می‌شود، اما ارتباط آن‌ها با دیتابیس نسخهٔ برگشتی نیاز به تطبیق دارد. باز کردن archive روی مسیر فعال با overwrite، روش این rollback نبوده است و در این راهنما توصیه نمی‌شود.
