## وضعیت ثبت‌شده، نه مشاهدهٔ زنده

این فهرست از نتایج موجود تهیه شده است. اصلاح مسئلهٔ باز یا انجام تست جدید باید با تاریخ، revision و مدرک تازه ثبت شود؛ گسترش مستندات به معنی رفع آن مسئله نیست.

| حوزه | پوشش ثبت‌شده | حد یا کار باز |
| --- | --- | --- |
| ترجمه | ممیزی منابع نهایی موفق | بازبینی انسانی و محتوای ذخیره‌شده مستقل است |
| login | دو زبان و ظاهر موفق | خطای درخواست ناشناس time-entry باقی است |
| تقویم مشترک | grid شمسی و ISO بررسی شد | همهٔ native inputهای ماژول‌ها پوشش ندارند |
| FullCalendar | label شمسی | planning interval میلادی |
| گانت | label/مرزهای بصری مرتبط | همهٔ تعاملات زمان‌بندی جامع تست نشده‌اند |
| RTL | مسیرها و منوی مشخص بررسی شد | تمام legacy UI و drag-and-dropها نه |
| فونت | وب و computed style بررسی شد | همهٔ PDFها و ایمیل‌کلاینت‌ها نه |
| Production | health، داده، ورود عمومی و asset | ورود احراز‌شده با رمز حساب موجود انجام نشد |
| rollback | restore و boot قدیمی موفق | rollback واقعی Production اجرا نشده |

## گزارش صحیح خطای شناخته‌شده

پیام نیاز به احراز هویت در login جدا از وضعیت HTTP صفحه ثبت شده است. برای پذیرش یک تغییر لوگو می‌توان آن را مسئلهٔ قبلی مستقل دانست، اما نباید از گزارش نهایی حذف و ادعای «بدون خطای JavaScript» کرد.

## اولویت‌بندی اصلاح بعدی

ابتدا اثر واقعی روی کاربر، مسیر بازتولید و محدودهٔ داده را مشخص کنید. سپس تست مرتبط را طراحی کنید. برای رفع خطای ناشناس، مجوز endpoint را عمومی یا احراز هویت را ضعیف نکنید. برای رفع تقویم یک component، قرارداد ISO سراسری را عوض نکنید.

پس از اصلاح، فقط نتیجهٔ اجرای واقعی را به این جدول اضافه کنید. تا آن زمان وضعیت باید همان «باز/تأییدنشده» بماند.
